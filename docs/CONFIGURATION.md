# Configuration

[Documentation index](README.md) · [Getting started](GETTING_STARTED.md) · [Troubleshooting](TROUBLESHOOTING.md)

Settings are generated by BepInEx in `BepInEx/config/org.repo.rest-api.cfg` within the active game directory or mod profile. Close the game before editing and restart afterward. The file contains your bearer token; keep it private.

## All settings

| Section | Key | Default | Meaning |
|---|---|---|---|
| HTTP | Enabled | true | Start the HTTP listener after scene activation |
| HTTP | Host | 127.0.0.1 | Literal listen IP address |
| HTTP | Port | 17453 | TCP port, 1–65535 |
| HTTP | RequireAuth | true | Require a bearer token on every route |
| HTTP | AllowRemote | false | Explicit opt-in for a non-loopback bind |
| HTTP | AuthenticationToken | generated | 32 cryptographically random bytes encoded as Base64 on first run |
| Limits | MaxRequestsPerSecond | 20 | Global authenticated request limit per rolling second |
| Limits | MaxSpawnQuantity | 10 | Maximum entity count per spawn command; supported range 1–100 |
| Limits | MaxRequestBytes | 16384 | Maximum UTF-8 request body bytes; supported range 128–1048576 |
| Limits | QueueCapacity | 64 | Game command capacity and separate HTTP concurrency limit; range 1–4096 |
| Limits | RequestTimeoutMs | 5000 | Queue deadline and separate upload/response timeouts; range 100–60000 ms |
| Limits | CommandsPerFrame | 2 | Queue entries processed per Unity Update; range 1–10 |
| Diagnostics | Verbose | false | Log action execution durations |

Catalog metadata is cached for up to three seconds and refreshed for mutations/session changes. Idempotency storage has a fixed 2048-key capacity and retains outcomes for at least 600 seconds in process memory. These are not configurable settings in this version.

## Authentication

Use the generated token in `Authorization: Bearer <token>`. Tokens must have at least 43 characters when authentication is enabled. Leave the generated random token in place unless you are deliberately replacing it with another strong credential. The normal log does not print tokens or request headers.

To rotate a token, close the game, clear `AuthenticationToken`, restart and load the newly generated value in your clients. Existing client terminals still contain the old token until you reload their environment variables. See [token setup](GETTING_STARTED.md#load-your-token).

## Remote binding

Loopback is the default. A non-loopback bind requires all three:

- `AllowRemote = true`.
- `RequireAuth = true`.
- An authentication token at least 43 characters long.

The server uses HTTP. Use a trusted network/VPN or a TLS reverse proxy for remote access. Changing a client's `REPO_API_URL` does not change the server bind address. There is no browser CORS support.

## Client settings

These environment variables configure the example consumers, not the plugin:

| Variable | Default | Meaning |
|---|---|---|
| `REPO_API_TOKEN` | required | The plugin's AuthenticationToken |
| `REPO_API_URL` | `http://127.0.0.1:17453` | Base URL for all four example clients |
| `REPO_API_CONFIG` | none | Convenience variable used by the Bash token-loading instructions |

Example clients use a 15-second client timeout. The JavaScript constructor also accepts `timeoutMs`, and the Python constructor accepts `timeout` in seconds. A client timeout does not cancel an action that already started. Keep the printed idempotency key and original body when the outcome is unclear.

Spawn diagnostics report catalog, placement and native instantiation durations when `Verbose=true`, and automatically for spawns taking at least 100 ms. A slow spawn log includes the last stage reached; stage durations describe completed phases. Native instantiation includes the synchronous REPOLib/game call and can still hitch on first asset initialization.
